# ADR 0002: Use SDK tools through one verification entry point

Status: Accepted

Date: 2026-10-17

## Context

Local developers, agents, and CI need the same checks on three operating systems.
Bootstrap must minimize extra tools and dependencies.

## Decision

Use `dotnet msbuild eng/verify.proj`. MSBuild runs locked restore with NuGet audit,
format verification, Release compilation with SDK analyzers, xUnit tests, and managed output reproducibility.
CI calls this command without repeating its internal steps.

Pin the SDK with roll-forward disabled. Centralize compiler settings and package
versions. Commit package lock files. Enable deterministic builds and CI path
normalization in every environment. Map repository source paths to `/_/`. Pin GitHub Actions by commit SHA.

Use xUnit v3 through Microsoft Testing Platform, selected in `global.json`.
Its native runner provides `dotnet test` and built-in TRX reports without a test
SDK, VSTest adapter, or report extension. An execution check rejected the default
VSTest path with the selected xUnit and .NET versions. Avoid additional analyzer,
architecture, coverage, or task-runner packages at bootstrap.

xUnit generates an entry-point namespace from the absolute project path. A
two-path build comparison detected different test DLL and PDB hashes. Disable
that generated entry point and call its public MTP runner from a fixed source
entry point. Keep MTP extension registration generated by its package. The
comparison then produced matching hashes for all four managed assemblies and PDBs.

For [issue #9](https://github.com/daniel-kindl/tangopad/issues/9), add the
package-free `eng/BuildVerification` executable. The final verification stage
runs it after tests and report validation. The tool invokes the same `Restore`
and `Build` targets in two fresh source trees. `Compile` uses `Build` after
format verification. The isolated builds do not repeat formatting or tests. The shared build command
uses `--disable-build-servers` so persistent workers cannot retain package task
assemblies when temporary caches are removed.

Snapshot Git-tracked files and non-ignored untracked files from the working tree.
Exclude deleted files, `bin`, `obj`, `artifacts`, and Git metadata. Reject source
file links. Copy the snapshot to two new temporary paths. Give each build its own
NuGet package, HTTP, plugin, and scratch directories. Use locked restore without
HTTP-cache reuse. Check that both builds use the pinned SDK. Disable Avalonia telemetry for the
isolated builds so its background collector cannot prevent Windows cache cleanup.
Avalonia 12.1.4 does not apply PathMap when it writes compiled AXAML symbols.
This limitation blocks the compiled AXAML migration in PR #26.
Do not rewrite compiled DLL or PDB bytes in that presentation refactor.
Do not exclude Editor.App from the comparison.
[Compiled AXAML path mapping](../avalonia-pathmap.md) records the reproduction and
[issue #28](https://github.com/daniel-kindl/tangopad/issues/28) tracks a separate build solution.

Compare each solution project's evaluated Release `TargetPath` DLL and adjacent
portable PDB with SHA-256. Compute relative outputs from the evaluated project
directory so macOS temporary path aliases do not escape the comparison root. Require managed assembly metadata and readable portable
PDB metadata. Missing outputs, mismatched hashes, an empty selection, overlapping
build directories, output links, and paths outside a build directory fail the check.
Exclude copied package DLLs, native libraries, apphosts, resources, and packaging
outputs. These are not the selected project assembly and symbol outputs.

Record source hashes, the base commit, SDK, host, configuration, absolute build and
cache paths, build logs, and both output hash manifests under
`artifacts/reproducibility`. The source hashes identify uncommitted changes that
the base commit alone cannot identify. Remove temporary builds and caches after
the run. CI uploads the evidence separately for each host.

## Consequences

Restore requires NuGet access. Audit warnings, including source failures, are
errors. All known vulnerability severities block verification. A clean audit is
a check against current advisory data, not proof that a dependency has no defect.

Determinism covers managed build outputs from the same inputs and pinned tooling.
It does not claim reproducible signed installers or native dependencies. Those
artifacts do not exist yet. A local build cannot prove native startup on another OS.
[ADR 0003](0003-native-startup-verification.md) runs one native startup check on the current host.

SDK updates require a coordinated `global.json` change. Package updates require
central-version and lock-file changes. Formatting and compiler analysis share the
same `.editorconfig`. New external tools need a concrete gap and a documented decision.
