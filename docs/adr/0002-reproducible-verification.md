# ADR 0002: Use SDK tools through one verification entry point

Status: Accepted

Date: 2026-10-17

## Context

Local developers, agents, and CI need the same checks on three operating systems.
Bootstrap must minimize extra tools and dependencies.

## Decision

Use `dotnet msbuild eng/verify.proj`. MSBuild runs locked restore with NuGet audit,
format verification, Release compilation with SDK analyzers, and xUnit tests.
CI calls this command without repeating its internal steps.

Pin the SDK with roll-forward disabled. Centralize compiler settings and package
versions. Commit package lock files. Enable deterministic builds and CI path
normalization in every environment. Map repository source paths to `/_/`. Pin GitHub Actions by commit SHA.

Use xUnit v3 through Microsoft Testing Platform, selected in `global.json`.
Its native runner provides `dotnet test` and built-in TRX reports without a test
SDK, VSTest adapter, or report extension. An execution check rejected the default
VSTest path with the selected xUnit and .NET versions. Avoid additional analyzer,
architecture, coverage, or task-runner packages at bootstrap.

xUnit generates an entry-point namespace from the absolute project path. A
two-path build comparison detected different test DLL and PDB hashes. Disable
that generated entry point and call its public MTP runner from a fixed source
entry point. Keep MTP extension registration generated by its package. The
comparison then produced matching hashes for all four managed assemblies and PDBs.

## Consequences

Restore requires NuGet access. Audit warnings, including source failures, are
errors. All known vulnerability severities block verification. A clean audit is
a check against current advisory data, not proof that a dependency has no defect.

Determinism covers managed build outputs from the same inputs and pinned tooling.
It does not claim reproducible signed installers or native dependencies. Those
artifacts do not exist yet. A local build cannot prove native startup on another OS.

SDK updates require a coordinated `global.json` change. Package updates require
central-version and lock-file changes. Formatting and compiler analysis share the
same `.editorconfig`. New external tools need a concrete gap and a documented decision.
